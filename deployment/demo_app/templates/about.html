Safety, data and intended use

What this local competition prototype can—and cannot—support.

Designed for this demo

  • Show a human-in-the-loop case and queue workflow using fictional records.
  • Run the real V3 checkpoint on explicitly confirmed fundus/retina images.
  • Record doctor-entered priority approval and preserve an audit trail.
  • Simulate capacity, appointments, queue ageing and exports locally.

Not designed for

  • Diagnosis, treatment, surgery selection or real scheduling.
  • Slit-lamp cataract detection, severity grading, LOCS grading or urgency.
  • Automated clinical priority. Every tier is manually entered by a doctor.
  • Clinical performance claims or deployment with patient data.

Data boundary

The 16 built-in cases are clearly fictional interface fixtures with IDs beginning DEMO-. Dashboard numbers and appointment capacity are simulated. They are never training data.

Original datasets remain read-only and outside the demo database. Uploaded demo images are validated, stored under generated names in the local app data directory and never transmitted to an external service.

Evidence boundary

The current model uses four fundus folder labels. Its 91-image final test is an image-level split because reliable patient IDs were unavailable. Softmax scores do not express clinical certainty. The missing slit-lamp labels and unusable 165-byte Excel lock file block supervised severity work.
